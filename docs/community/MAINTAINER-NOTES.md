# Community follow-through

Use GitHub Discussions as the public home for introductions and questions. Keep reports and decisions linked to issues so Discord feedback is not lost.

When a tester joins, ask which workflow and environment they can test. Do not collect personal email addresses or credentials. Start with the sample checklist. Connected-account testing is optional.

For each contribution:
1. Acknowledge the report or proposed task and check for duplicates.
2. Agree on a small scope and acceptance checks in the issue.
3. Review the behavior, tests, and account/data implications.
4. Link the merged PR to the issue and credit its contributor.
5. Ask the reporter to retest when relevant; the product owner retains release acceptance.

Publish milestone updates when there is meaningful progress. Include what changed, who contributed, what remains broken, and the next specific invitation. Avoid repeating promotional posts without new information.

Initial recruitment target: five testers and one or two C++/Qt contributors. A published invitation is not evidence that anyone has joined; track actual volunteers through their discussion replies.
